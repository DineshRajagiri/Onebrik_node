OneBrik – Customer flow

Cart → Address → Order → Payment (Razorpay). How everything links together.

Flow diagram

GUEST (no login)
  Create Device          → deviceId
  Get Cart?deviceId=...  → cartId
  Get Items              → productId, variantId, price
  Add Cart Item          → cart has items

  User logs in (OTP or password)  →  JWT

LOGGED IN (JWT)
  Get Cart?deviceId=... + Auth    →  cart linked to customer
  Get Addresses?deviceId=...      →  cart linked, addressId
  Create Order { addressId }      →  orderId
  Razorpay Create Order { orderId } → paymentId, razorpayOrderId, key
  [Frontend: Razorpay Checkout]   →  user pays
  Razorpay Verify                 →  Payment SUCCESS, Order confirmed
  Get Order                       →  order + paymentStatus

Links:  Cart <--deviceId--> Customer    Payment <--orderId--> Order

Step 1 – Auth (get JWT)

1 JWT

Customer logs in via OTP or password. You need the accessToken for steps 3–6.

Send OTP
POST /api/auth/customer/send-otp
{"email": "user@example.com", "purpose": "login"}
Verify OTP (get token)
POST /api/auth/customer/verify-otp
{"email": "user@example.com", "otp": "123456", "purpose": "login"}

Response: data.accessToken → use as Authorization: Bearer <token>

Step 2 – Device & Cart (guest, no JWT)

2 No JWT

Create a device and get a cart by deviceId. Add items using productId and optional variantId + price from Get Items.

Create Device
POST /api/customer/device/create
{"deviceToken": "unique-token", "deviceType": "web"}

Response: data._id or data.deviceId → save as deviceId.

Get Cart (by device)
GET /api/customer/cart?deviceId=<deviceId>

Response: data.cart._id → cartId. data.items[] → cart items.

Get Items (products + variants)
GET /api/customer/items?page=1&limit=20

Each item: id (productId), variants[] with _id (variantId), salePrice, offerPrice. Use offerPrice ?? salePrice as price.

Add to Cart
POST /api/customer/cart/:cartId/items
{
  "productId": "<from item.id>",
  "variantId": "<optional, from item.variants[]._id>",
  "quantity": 2,
  "price": 199
}

Step 3 – Address (JWT + link cart)

3 JWT

Send deviceId with the first address request so the guest cart is linked to the logged-in customer.

Get Addresses (with deviceId → links cart)
GET /api/customer/address?deviceId=<deviceId>

Header: Authorization: Bearer <token>

Cart for this deviceId is now linked to the customer. Response: list of addresses → pick addressId.

Create Address (with deviceId → links cart)
POST /api/customer/address
{
  "addressType": "home",
  "fullName": "John Doe",
  "mobileNumber": "9876543210",
  "addressLine1": "123 Main St",
  "city": "Mumbai",
  "state": "Maharashtra",
  "postalCode": "400001",
  "country": "India",
  "deviceId": "<deviceId>"
}

Include deviceId in body to link cart. Response: data._id → addressId.

Step 4 – Order (JWT)

4 JWT

Create order with addressId. Optionally send deviceId again to link cart if not done at address step.

Create Order
POST /api/customer/order
{
  "addressId": "<addressId>",
  "discountAmount": 0,
  "shippingCharges": 0,
  "notes": "",
  "deviceId": "<optional>"
}

Response: data.order._id → orderId. Order is linked to cart items and address.

Step 5 – Payment Razorpay (JWT)

5 JWT

Create a Razorpay order for your orderId. Frontend opens Razorpay Checkout. After payment, verify so the backend updates Payment + Order status.

Create Razorpay Order (links Payment to Order)
POST /api/customer/payment/razorpay/create-order
{"orderId": "<orderId>"}

Response: razorpayOrderId, key, amount (paise), paymentId. Backend creates Payment with orderId + razorpayOrderId.

Frontend: Razorpay Checkout

Use key and razorpayOrderId with Razorpay.js. On success you get razorpay_order_id, razorpay_payment_id, razorpay_signature.

Verify Payment (updates Payment + Order)
POST /api/customer/payment/razorpay/verify 
{
  "razorpayOrderId": "order_xxx",
  "razorpayPaymentId": "pay_xxx",
  "razorpaySignature": "signature_from_checkout"
}

Backend finds Payment by razorpayOrderId, verifies signature, sets payment SUCCESS and order confirmed.

Razorpay testing – what you need

To test payments without real money:

  • Test mode – In Razorpay Dashboard, switch to Test Mode (toggle top-left). Generate API Keys under Settings → API Keys. Use these only in test mode.
  • Env vars – Your backend needs: 
    RAZORPAY_KEY_ID=rzp_test_xxxxx
RAZORPAY_KEY_SECRET=your_test_secret
    Restart the server after setting these.
  • Test cards – Use Razorpay’s test cards (e.g. card number 4111 1111 1111 1111). Any random CVV and any future expiry date. See Razorpay test card details for more (Indian, international, EMI).
  • OTP – When prompted: OTP < 4 digits → payment fails; OTP 4–10 digits → payment succeeds.
  • Test UPI – Use success@razorpay for success, failure@razorpay for failure.
  • Webhooks (optional) – For local testing of webhooks, use a tunnel (e.g. ngrok) and set the webhook URL in Dashboard.

No real money is charged with test keys. Do not use test cards in Live mode.

Step 6 – Get Order / Payment status

6 JWT
Get Order (includes payment status)
GET /api/customer/order/:orderId

Response: paymentStatus, paymentGateway, transactionId, paymentDate, orderStatus.

Get Payment Status
GET /api/customer/payment/status/:paymentId

How things link

Link How
Cart ↔ Customer Send deviceId on first Get Addresses, Create Address, or Create Order (with JWT). Guest cart for that device is merged to the customer.
Payment ↔ Order Payment has orderId. Create Razorpay Order sends orderId; Verify updates that Payment and the Order (orderStatus: confirmed).
Product / Variant in Cart productId = product id from Get Items; variantId = optional, from item.variants[]._id; price = variant’s offerPrice or salePrice (or product minPrice if no variant).

Base URL: /api (e.g. http://localhost:3001/api). Use the Postman collection in this folder for actual API calls.
